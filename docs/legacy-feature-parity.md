## 逐字节兼容结论

帧格式为 `FF DIR LEN FUNC PAYLOAD CHECKSUM`。`DIR=FC`表示Jetson到STM32，
`DIR=FB`表示STM32到Jetson；总长为`LEN+2`，载荷长为`LEN-3`。校验是从
`LEN`到最后一个载荷字节的8位累加和。

| 消息 | 完整字节（示例） | 结论 |
|---|---|---|
| 自检请求 | `FF FB 04 51 00 55` | 兼容 |
| 自检成功 | `FF FC 05 51 01 00 57` | 兼容 |
| 巡检开始 | `FF FB 04 A3 01 A8` | 兼容 |
| 开始接受 | `FF FC 05 A3 01 01 AA` | 兼容 |
| 开始拒绝 | `FF FC 05 A3 01 00 A9` | 兼容 |
| 巡检停止 | `FF FB 04 A3 00 A7` | 兼容 |
| 停止ACK | `FF FC 05 A3 00 01 A9` | 兼容 |
| 急停触发 | `FF FB 04 A4 01 A9` | 兼容 |
| REMOTE报告 | `FF FB 04 A5 00 A9` | 兼容 |
| STANDBY报告 | `FF FB 04 A5 01 AA` | 兼容 |
| 运动示例 | `FF FC 0A 12 01 00 80 00 00 FF 7F 1B` | 兼容；小端有符号int16 |

`0x12`载荷依次为`car_type,Vx_lo,Vx_hi,Vy_lo,Vy_hi,Vz_lo,Vz_hi`，速度单位依次为
mm/s、mm/s、mrad/s。新固件保留`B0-B6`扩展码，但当前部署闭环不使用没有对端实现
的扩展消息。

## 原问题闭环

旧RC源码在INSPECTING开头直接返回，并把CH5停止分支注释掉，因此巡检中CH7、CH6和
CH5停止均不能退出。新链路保留RC采集，CH7可从INSPECTING直接进入EMERGENCY，CH6
可进入STANDBY或REMOTE_ARMING；离开INSPECTING会清除Jetson命令并锁存`A3 00`。
端到端测试覆盖接受、速度、完成、取消、清旧速度和REMOTE重新取得控制。RC样本按到达
顺序消费；解除后同批再次触发时保持EMERGENCY，整体RC信号无效时拒绝解除急停。

## 尚不能宣称完成的系统闭环

- 部署版`stm32_node.cpp`没有主动发送巡检完成或取消消息，也不支持`B3/B4`。固件端已
  支持，但真实“导航完成→STM32退出INSPECTING”仍需修改并测试Jetson桥。
- 部署版`stm32_node.cpp`只在自身处于STANDBY时真正进入INSPECTING，却无论是否进入
  都回复`A3 01 01`。这会造成两端状态分裂；Jetson端必须只对真实接受回复成功。
- 部署桥的`self_check_done_`置位后会忽略后续自检请求。若Jetson不断电而STM32单独
  复位，STM32会安全地停在BOOT_SAFE但无法继续；Jetson端应改为幂等回复或引入会话。
- `0x51`同时承载历史VERSION与SELF_CHECK，载荷`01 00`无法从字节区分“版本1.0”和
  “自检成功”。当前请求窗口只能降低误收概率，不能提供强身份或新鲜度证明。
- 部署桥没有独立STM32心跳/状态总帧，`B5/B6`载荷与周期无双方确认，不能伪造兼容性。
- 方向映射、最大RPM、RC车辆尺度、急停距离、MSSD停止效果和蜂鸣器实际声响仍需实机标定。
- 抱闸物理语义与到位反馈未验证，当前保持禁用。

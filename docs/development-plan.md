# 开发计划

## 阶段0：离线基础设施（当前阶段）

- 固化CubeMX+CMake空工程Git基线。
- 建立硬件映射、安全需求和待验证清单。
- 建立不依赖HAL的纯状态机及主机单元测试，使用REMOTE_ARMING执行遥控中位准入，并用INSPECT_REQUESTED表达Jetson确认窗口。
- 将状态机编译进STM32目标，但不在 `main()` 中调用。

## 阶段1：离线输入与协议解析

- 为遥控脉宽采集设计边界检查、去抖、CH1/CH2中位确认、失联超时和主机可测的解析层。
- 为Jetson协议设计流式拆包、校验、序号/新鲜度和超时策略。
- 为巡检请求设计接受、拒绝、取消和请求超时事件的适配层。
- 使用录制数据或合成数据测试，不连接车辆执行机构。

## 阶段2：安全监督与只读通信

- 设计统一安全监督器，明确急停、故障、通信超时和状态机动作的优先级。
- 在确认厂商协议和接线后，先实现只读状态查询；仍不写速度或刹车寄存器。
- 明确看门狗、故障锁存和复位恢复策略。

## 阶段3：受控硬件验证

- 完成 [待硬件验证清单](hardware-validation-pending.md) 后另行评审准入。
- 先进行逻辑分析仪/示波器验证，再进行断开动力的通信验证。
- 后续如获批准，采用架空轮、限速、物理急停、双人监护和逐级Go/No-Go流程。

## 阶段4：车辆级集成

- 只有前述阶段均通过并形成记录后，才设计MSSD写寄存器、零速确认和抱闸执行层。
- 对遥控、待机、巡检、急停、通信丢失、复位和异常路径进行系统级验收。
